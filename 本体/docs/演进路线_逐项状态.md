### 0.2 实现清单

**新增文件**
- `本体/usys.h`：syscall 6~19 编号 + `struct ustat`（32B，显式 padding 保证布局确定），用户态/内核/宿主单测共用 ABI。
- `本体/usysfd.h` / `本体/usysfd.c`：统一 fd 表（UFD_MAX=24，0/1/2 console、3..5 历史 g_fd、6..23 新对象）+ 环形 pipe（UPIPE_RING=1024B，**ring 用 `kmalloc` 动态分配**）+ dup/dup2/close 引用计数。纯 C、freestanding，可宿主单测。
- `本体/test_usysfd_host.c`：**57/57**，覆盖 8 档 fd 分配、pipe 回绕数据顺序、dup/dup2 共享、批量 pipe 后 `ufd_reset` 一次性释放零泄漏。
- `本体/user/u55_util.h`、`user/u55_systest.c`、`user/u55_sh.c`：两个 -nostdlib EL0 程序。u55test 逐项冒烟 19 号 syscall 输出结构化 `[R55] key=value`；u55sh 装配管道。
- `本体/test_round55.py`：双路判据（TCG / 真机 KVM），本地 TCG **25/25**。

**修改文件（严格最小侵入）**
- `本体/user/user.h`：新增 14 个 syscall 薄封装（0~5 号老接口逐字保留）。
- `本体/kernel.c`：① include `usys.h/usysfd.h`；② 辅助层（`g_ucwd` 独立 cwd + `u_resolve` 复刻 path_resolve + `u_range_ok` 用户指针校验 + `fill_ustat` + `getdents` 回调）；③ 0/3/4 号 syscall **插入 pipe 转发钩子**——`is_ufd_obj()` 仅在 fd 确实指向 pipe 时为真，未 dup2 时 0/1/2 恒 CONSOLE、3..5 恒 FREE，钩子不触发，老路径逐字不变；④ 新增 6~19 号分发；⑤ `run_userprog` 装载前 `ufd_reset()` 复位 fd/pipe 层（跨 run 零泄漏）+ 复位独立 cwd；⑥ `kernel_main` 开机 `ufd_init()`（静默）。**0 个新增 cmd_***。
- `本体/build.sh`：`KERN_SRCS` 加 `usysfd.c`；编 `u55test.elf`/`u55sh.elf`「只编不内嵌」（判据脚本经 b64 注入）。

### 0.3 关键设计决策（都写进代码注释）

1. **0~5 号 syscall 逐字不动**：老 ELF 程序（hello/cat/args/bad/hang）与 `test_stage5b_elf.py` 33 项判据全依赖它。`bad.c` 的 `[run] 用户指针越界，拒绝: p=0x0000000040080000` 逐字断言必须保留——pipe 转发钩子对非法 fd 一律不触发。
2. **cwd 隔离**：syscall 用独立 `g_ucwd`，与 shell 的 `cwd` 彻底隔离；用户程序 chdir 不污染内核 shell 当前目录。`u_resolve` 复刻 `path_resolve` 但以 `g_ucwd` 为基准，绝不改 `path_resolve` 本身（29 条基线依赖它）。
3. **用户程序不进内核镜像**：为避免改启动日志 `[user] /bin/...` 种子行、`ls /bin` 的 5 个文件、`df` 数值，两个 ELF 由 `test_round55.py` 经 `b64in` 注入 `/home`。
4. **fs 返回值规整**：`fs_mkdir/fs_createfile/fs_rename` 成功返回 ino(>0)，syscall 层统一 `(r<0)?-1:0` 规整为用户态约定。
5. **`fs_rename` 不支持移动目录**（-3，既有设计边界）：故 rename 判据改用「文件」验证，另加 `SYS_creat` 让测试自洽；mkdir/unlink 单独验证目录（空目录可删）。

### 0.4 诚实边界（第 55 轮）

1. **2.3「shell 迁出内核」未做**：本轮的 `u55sh` 是**管道演示程序**，不是交互 shell。真正的 shell 迁出需要 `fork/execve/wait` 进程模型（文档把它排在 2.3，实现却依赖优先级 1 的 3.2 进程模型），**第 57 轮**才具备条件。当前仍是「一次 `run` 装载一个 ELF、exit 回内核」的单进程模型。
2. **管道不是并发多进程**：单进程模型下按「写满 → 关写端 → 读」分阶段装配，不阻塞、无调度；`dup2` 到 0/1/2 的重定向在**同一进程内**生效。真 `ls|grep|wc` 的「三个独立进程并发」留给第 57 轮。
3. **`kill` 是占位语义**：单进程无其它进程可杀，pid!=1 一律拒、pid==1 的 TERM 只回 0 不真杀；真信号/进程组是第 58 轮。
4. **`getdents` 是路径+缓冲的简化接口**：不是 fd 型 `getdents64`，返回值是写入字节数；由 `fs_list` 列目录项拼 `"name\n"`。
5. **第 54 轮 7 个 `cmd_*` 技术债仍在**：本轮严守 §七「零新增 cmd_*」，但**未把第 54 轮那 7 个迁出**——那要等用户态 shell 真正做成（第 57 轮）。§六技术债不销账。
6. **真机 KVM 双路未复验**：本地沙箱 x86_64 无 aarch64 KVM；NAS SSH 通道本轮未探通（延续第 54 轮状态）。`test_round55.py` 报告 KVM 列「—」= 未执行，不是 0、不是通过。
7. **用户态程序是「测试资产」不是「发行版程序」**：`/home/u55test`、`/home/u55sh` 由判据脚本临时注入，不随 ISO 分发；没有 `PATH`、没有 `/bin/sh`。

## 九、诚实边界（累计列出）

1. **不是「全部基本解决完成」**：VFS、每进程 TTBR0、fork/exec/wait、用户态交互 shell、
   TTY/信号、socket、ZFS-lite、Jail-lite 等**架构级能力一项都未实现**。两轮只做实了
   「可真实落地 + 可量化验收」的地基、syscall 扩容与低风险增量项，逐项给出状态。
