## 零点八、第 58 轮 B（58.0-B）：抢占式调度地基（新增核对）

> 用户本轮要求「全面更新一遍系统，方向自定」。按 §十 新排期锁定 58.0-B 的可安全落地部分：
> 抢占式调度的**地基**——五态调度状态机 + 时间片 + 轮转 runqueue + yield + 统计。真·抢占

### 0.8.3 诚实边界（第 58.0-B 轮）
1. **yield 是记账语义，不是真抢占**：当前合作式模型下 yield 只更新调度视图的就绪态与统计
   （并有独立进程时经 pick_next 选下一个就绪者），**不切 EL0 异常帧**；真抢占要在 IRQ 里
   保存/恢复进程帧，依赖独立内核栈 + fs scratch 加锁，后置。
2. **g_sched 是平行视图**：与 g_procs 按 pid 对齐，只做「谁该跑」的记账/统计，不参与真实
   进程切换决策；pid=1 初始进程在调度表外（current 记 0）。
3. **仅一层 fork、单活跃子**：与第57/58轮一致；多子并发（兄弟轮转）需真抢占支撑，本轮
   u59 严格单子分流（多子曾产生孤儿实体，已如实记录并规避）。
4. **时间片到期只记账**：tick 递减 slice、到期重填并计 slice_expires，但不触发强制切换。
5. **schedstat 是静态快照**：96B 定长结构逐字段写，读的是记账视图而非常规 /proc 文件。
6. **真机 KVM 双路未执行**：见 0.8.2；报告 KVM 列「—」= 未执行，不冒充双路通过。
7. **新增能力未进 help/golden**：存在性由 test_round59.py 26 项 + 宿主 72 项独立证明。

### 0.7.3 诚实边界（第 58.0-A 轮）

1. **仍是合作式一层 fork**：pid=1 父 + NPROC-1 子，父 `wait` 才让出，子 `procexit` 回父；
   无抢占、无嵌套 fork、无兄弟并发（58.0-B）。
2. **fork 仍全拷贝**：COW 按用户要求后置到 VM/页引用计数稳定后；本轮 FD 层已具备 ofd
   引用计数，为后续 COW 的页引用计数打了样。
3. **execve 第二参是打包参数行字符串**（空格分隔），非完整 `argv[]` 指针数组；argv0 固定
   为程序路径（Unix 惯例），argline 首词落 argv1。完整 argv[]/envp 解析列为后续。
4. **pipe 层（usysfd fd 6..23）仍是全局**，未纳入每进程表；本轮每进程化只覆盖普通文件
   fd（0..5），老管道演示零扰动。pipe 的每进程隔离列为后续。
5. **父 pid=1 的 fd 仍走全局 g_fd**：每进程表只作用于 fork 子进程——这是保 golden/stage5b
   零扰动的关键取舍，也是「渐进接管」而非「全量替换」（与第 56 轮 VFS 同样的策略）。
6. **子进程 read 按 ino 从 fs 重读**（OFD 不存文件缓冲，省 BSS）；共享的是 off/ino/len，
   满足 Unix「共享打开文件描述」语义，但与真 OFD 缓存文件内容的实现有差异。
7. **真机 KVM 双路未执行**：见 0.7.2；报告 KVM 列「—」= 未执行，不冒充双路通过。

## 零点六、第 57 轮：进程模型（新增核对）

### 0.6.1 路线文档第 57 轮验收判据逐条对照

| 文档要求 | 本轮实现 | 状态 |

| ① 每进程 TTBR0 + 内核空间共用（KPTI 暂不做） | 每个子进程复制一张用户区 L3 表 + 独立物理页池；切换改 `l2_ram[1]` 表基址 + `tlbi vmalle1`。内核半共用（l3_kern/l2_dev 不动），与文档 §3.2 步骤①「KPTI 暂不做」口径一致 | ✅ 等价简化 |

| ③ `execve` + `exit` + `wait` + 僵尸回收 | `SYS_wait` 让出/回收、`SYS_procexit` 退出码回传、`SYS_getpid` 当前 pid；判据 status=7、wait_ret=子pid、二次 run 进程表干净；`SYS_execve` 本轮返回 -1（占位，见边界） | 🟡 execve 占位 |
| ④ `g_fd` 改为 `proc->files` | 未做：本轮 fork 全拷贝不含 fd 表；合作式串行下父子不同时持有 fd，暂不串扰。fd 每进程化留后续（诚实边界） | ⬜ 见边界 4 |
| ⑤ 两进程互写对方地址触发 fault，不串内存 | 子进程只能经自己的 L3 表访问自己物理页；父 L3 未被改。判据 g_shared 隔离正向证明；越界互写 fault 由既有 EL0 权限机制保证 | ✅（正向隔离判据） |

### 0.6.3 关键设计决策（都写进代码注释）

1. **整表复制即换地址空间**：沿用 mmu_init 注释原话；子进程复制用户 L3 + 独立物理页，切 `l2_ram[1]` 基址。比每进程整套 l0/l1/l2 更省内存，内核半共用。
2. **合作式（非抢占）上下文切换**：单内核栈，切换 = 800B 异常帧整体拷贝（proc.c 单测第 10 项验证）；boot.S 的 SAVE/RESTORE_CTX 一行不改 → golden 零扰动。子不自动跑，父 `wait` 才让出，子 `procexit` 回父。
3. **页表权限按父 PTE 保留**：fork 复制用户页时保留父 PTE 低 12 位权限（代码段 USEREX 可执行、数据段 USERRW），只换物理地址。踩坑：首版一律写 USERRW 导致代码段 UXN=1，子一取指就 EC=0x20 fault——已修。
4. **pid 1 独立缓冲**：初始进程不占 `g_procs` 槽（`proc_alloc` 从 pid 2 起），现场存 `g_init_frame`；本轮支持一层 fork（父恒为 pid 1）。
5. **跨 run 零泄漏**：`run_userprog` 装载前（必须在 fill_pt 之前）与 `el1_landing` 都回收全部子进程页并切回全局 L3；`mmstat audit=0` 量化。
6. **老 syscall 零扰动**：0~21 全不动；getpid 门控增强（单进程恒 1）；新增能力不进 help/golden，靠 test_round57.py 21 项独立证明。

### 0.6.4 诚实边界（第 57 轮）

1. **合作式，非抢占式多进程**：父显式 `wait` 才让出，子 `procexit` 回父；无调度器、无时间片、无父子并发同跑。真·抢占调度是后续大工程。
2. **fork 是全拷贝，非 COW**：逐页复制 + 独立物理页（判据已证隔离），未做写时复制的资金/页表优化；每子最多 PROC_NPAGES=20 页（128KB+栈，够当前 <12KB 用户程序）。
3. **execve 占位**：`SYS_execve` 返回 -1；未在地址空间间真正替换镜像（依赖完整 ELF loader 与 fd 每进程化后再做）。
4. **fd 表未每进程化**：fork 不含 fd 表；合作式串行下父子不同时持有 fd，暂不串扰，但严格 POSIX fork 语义（步骤④）未兑现。
5. **仅一层 fork**：父恒为 pid 1，子不能再 fork（子 `procexit` 直接回 pid 1）；无进程树/兄弟并发。
6. **mmap 未做**：无用户态映射接口（文档 §四 mmap 仍 ⬜）。
7. **真机 KVM 双路未复验**：本地 x86_64 无 aarch64 KVM；NAS SSH 通道本轮未通（见 §九边界 10）。报告 KVM 列「—」= 未执行。
8. **用户态程序不随 ISO 分发**：`/home/u57proc` 由判据脚本经 b64 临时注入。

### 0.5.3 关键设计决策（都写进代码注释）

1. **老路径优先**：`fs_lookup` 命中即返回，VFS 完全不参与；`/etc/hostname`、`/nope` 等 29 条基线路径不会进入 VFS 钩子。
2. **VFS 不接管 open/read fd 层**：`SYS_open`(2)/`SYS_read`(3) 逐字不动（第 55 轮教训：老 syscall 零扰动）。伪文件用专用 `SYS_vfsread` 读，语义清晰、不动 fd 对象层。
3. **procfs 数据源回调注入**：`vfs.c` 不依赖 `kernel.c` 全局，通过 `procfs_set_source()` 注入 `mm_stat`/`tick`/`ncpu`/version 回调；宿主单测用假数据替代，验证「读的是回调而非常量」。
4. **挂载静默**：开机挂载不打任何日志，避免污染 golden 的启动日志逐字比对。
5. **零 malloc**：挂载表固定 8 项静态数组，伪文件内容现场生成到调用方缓冲，不占动态堆、不占 BSS 大块（仅增约 4KB，余量仍 20KB）。

### 0.5.4 诚实边界（第 56 轮）

1. **「跨挂载点 cp」未做全**：文档验收写「跨挂载点 `cp`」，本轮只做到**跨挂载点读**（loongfs 文件 vs procfs/devfs 伪文件用不同后端读出），但**没有实现 `cp` 把文件从 loongfs 写到 procfs 挂载点**（procfs 是只读伪文件，语义上也不该可写）。完整 `cp` 依赖 VFS 写接口 + `/mnt` 真实挂载，留后续轮次。
2. **VFS 是渐进式，不是全量替换**：`fs.c` 没有「降级为 loongfs 后端、所有 `fs_*` 调用改 `vfs_*`」——老命令仍直接调 `fs_*`，VFS 只接管 `/proc` `/dev` 两个新挂载点。文档 §3.1 的「加 FAT32/EXT2 不改上层」这一收益**尚未兑现**（需把上层全改 vfs_*）。
3. **`/proc` 是简化版**：只有 5 个固定伪文件，`uptime` 的空闲秒恒 0（诚实标注），非完整 Linux procfs。
4. **2.3 shell 迁出内核仍未做**：见 §零点一 0.4 第 1 条，依赖第 57 轮进程模型。
5. **真机 KVM 双路未复验**：本地 x86_64 无 aarch64 KVM；NAS SSH 通道本轮 21:08 探测端口 56484 仍 `NoValidConnectionsError`（延续第 54/55 轮）。报告 KVM 列「—」= 未执行。
6. **用户态程序不随 ISO 分发**：`/home/u56vfs` 由判据脚本经 b64 临时注入。

## 九、诚实边界（累计列出）

1. **不是「全部基本解决完成」**：交互 shell、抢占式调度、TTY/信号、socket、ZFS-lite、
   Jail-lite 等架构级能力未实现。四轮只做实「可真实落地+可量化验收」的地基、syscall
   扩容、VFS+伪文件系统、进程模型地基与低风险增量项。
2. **2.2 验收②未满足**：`stat` 仍显示开机秒数（保基线），真实墙钟在 `wall`/`ls -l`；ISO 内存盘重启不持久。
3. **2.3 shell 迁出内核未做**：`u55sh` 是管道演示程序，不是交互 shell；第 57 轮进程模型是地基，
   但 `execve` 占位、fd 未每进程化、无交互 shell，仍不足以迁出（见 §零点六边界 1/3/4）。
4. **第 54 轮 7 个 `cmd_*` 技术债仍挂账**：第 55/56/57 轮零新增但未迁出（见 §六）。
5. **管道是单进程分阶段装配**：非三进程并发；`kill` 是占位语义。第 57 轮进程是合作式一层 fork，
   未用于管道并发。
6. **`vmalloc` 未做**：第 57 轮进程用 kmalloc 分配用户物理页，未实现映射型 vmalloc/用户 mmap。
7. **第 56 轮「跨挂载点 cp」与 VFS 全量替换上层未做**：见 §零点五 边界 1/2；procfs 只读、简化版。
8. **真机 KVM 双路四轮均未复验**：本地 x86 无 aarch64 KVM，NAS SSH 通道本轮仍未通。报告 KVM 列「—」= 未执行。
9. **新增能力未进 `help`/基线**：存在性由 test_round54.py 22 项 / 55 项 25 项 / 56 项 19 项 /
   57 项 21 项 / 58 项 22 项判据单独证明。
10. **用户态程序不随 ISO 分发**：`/home/u55*`、`/home/u56vfs`、`/home/u57proc`、`/home/u58*` 由判据脚本经 b64 临时注入。
11. **第 57/58 轮进程模型边界**：合作式非抢占、fork 全拷贝非 COW、仅一层 fork、mmap 未做
    （§零点六 0.6.4）；第 58 轮已补 FD 每进程化 + 完整 execve，但 pid=1 仍走全局 g_fd、
    pipe 层仍全局、execve 第二参是打包参数行非 argv[]（详见 §零点七 0.7.3）。
    抢占式调度（58.0-B）、COW/用户 shell（58.0-C）按用户新排期后置。
