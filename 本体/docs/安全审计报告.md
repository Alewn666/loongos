## 三、高危发现（H）

### H1 `fm_full` 无边界字符串拼接 → 全局缓冲区溢出（本轮 GUI 生态引入）

- **位置**：`desktop.c:626-629` `fm_full()` 使用无边界 `my_strcpy`（`desktop.c:150`）拼接 `fm_path` + `/` + 目录项名；调用点：
  - `desktop.c:705` `fm_full(fm_path, f.name)` —— **目标缓冲就是 `fm_path[96]` 自身**，in-place 追加，路径逐层变长时越过 96 字节写向相邻全局（`G_launch_path` 等）；
  - `desktop.c:707-708` `char full[160]; fm_full(full, f.name); my_strcpy(G_launch_path, full);` —— `full` 最长可达 `96+1+61=158`，却拷进 **`G_launch_path[96]`**（`desktop.c:129`），**确定的全局缓冲溢出**；
  - `desktop.c:726` `my_strcpy(ed_path[96], G_launch_path)` —— 源若已因上一步失去 NUL 终止，继续越界读。
- **触发条件**：路径/目录名来自 `fs` 目录项（最长 61 字节），用户可通过 shell 或文件管理器创建深层/长名目录，再在 GUI 里逐层点进去。内核单地址空间、无写保护，越界写会破坏 `G_win`/`G_apps` 等全局状态，最坏可影响控制流。
- **修复建议**：
  1. 引入带 cap 的 `my_strncat(char *dst, int cap, const char *s)` / 统一 `PATH_MAX 160`；
  2. `fm_full` 增加 `out_cap` 参数，拼接前检查 `strlen(fm_path)+1+strlen(child)+1 <= out_cap`，超长直接拒绝并提示；
  3. 把 `fm_path`/`G_launch_path`/`ed_path` 统一扩到 160 或用同一 `PATH_MAX`；
  4. 补一个宿主单测：构造 90 字节路径 + 60 字节子目录名，断言不越界。

### H2 ELF 加载器 `phoff` 整数回绕 → 程序头表越界读

- **位置**：`kernel.c:1537` `if (eh->phoff + (u64)eh->phnum * eh->phentsize > (u64)n)`。
- **成因**：`phoff`（u64）、`phnum`/`phentsize` 全部来自用户提供的 ELF 文件。`phoff + phnum*phentsize` 在 64 位下可**回绕**成一个小值从而绕过检查，随后 `kernel.c:1546` `elf_buf + eh->phoff + i*phentsize` 越界读取程序头。另 `eh->phentsize` 未校验 `>= sizeof(struct elf64_phdr)`，可让程序头解析错位。
- **影响**：本地恶意 ELF 经 `run` 命令触发内核越界读 / 崩溃（DoS）。教学场景下非远程攻击面，但属明确缺陷。
- **修复建议**：先分别校验 `phoff <= n`、`phentsize >= 56`、`phnum <= (n-phoff)/phentsize`（用减法代替加法避免回绕）；对每个 phdr 再校验 `offset`/`filesz` 落在 `[0,n]`。

### H3 `u_strcpy` 只校验用户指针起点，未校验终点

- **位置**：`kernel.c:1604-1614`，用于 SVC `open(path,...)`（`kernel.c:1654`）。
- **成因**：`if (uptr < USER_BASE || uptr >= USER_END) return -1;` 仅检查**起始**指针；随后循环最多读 `max-1`(127) 字节 `((char*)uptr)[i]`。若用户把指针放在 `USER_END-1` 且不放 NUL，读取会**越过 `USER_END` 进入内核地址空间**——触发 EL1 数据异常（内核挂起/DoS）或读到越界内存。
- **对比**：同文件 `svc_dispatch` 的 write/read 分支（`1622/1643/1670`）都做了 `p+len < p || p+len > USER_END` 的回绕+上界校验，`u_strcpy` 是唯一的漏网。
- **修复建议**：改为 `if (uptr < USER_BASE || uptr >= USER_END || (u64)(max-1) > USER_END - uptr) return -1;`，并在循环内逐字节确认地址仍 `< USER_END`。

## 四、中危发现（M）

### M1 口令哈希比较非常量时间（时序侧信道）

- **位置**：`kernel.c:2092-2093` `for (j=0;j<64;j++) if (got[j] != buf[c3+1+j]) return -1;` —— 首字节不等即返回。
- **影响**：理论上可逐字节计时猜出哈希。本地串口/无高精度远程时钟环境下实际利用难度高，但实现应修正。
- **修复**：改为累积异或 `int diff=0; for(j=0;j<64;j++) diff |= got[j]^buf[c3+1+j]; return diff ? -1 : 0;`，保证恒定时间。

### M2 开机即 root、无登录门禁、DAC 形同虚设

- **位置**：`kernel.c:3455-3456` 开机 `fs_setuid(0)` + `auth_init()`；`kernel.c:3089-3098` `cmd_su` 仅在 `shell_uid != 0` 时校验口令（"root 切谁都免"为文档明示的教学简化）。
- **影响**：任何能接触串口/桌面 shell 的人**直接拥有 root**，口令系统只在"从 demo 切回 root"这一条路径上生效，不存在"登录认证"入口。作为"日常系统"这是根本性的鉴权缺失。
- **建议**：若要做日常系统，需引入开机登录（`login` 门禁）并把默认会话降为普通用户；至少在文档「诚实的边界」里显式写出"无登录认证"这一事实。

### M3 弱口令体系：自定义 KDF + 全局静态盐 + 默认口令公开

- **位置**：`auth_cred.h:14-15` 固定盐 `'LoongSlt'`（8 字节，全用户/全部署共用）、`AUTH_ITER 50000`；`crypto.c:97-115` `sha256_iter` 为自定义迭代 SHA-256（非 PBKDF2/bcrypt/Argon2），且 `crypto.c:103` 把口令**静默截断到 64 字节**；默认口令 `loong2026`/`demo2026` 明文写在 `kernel.c:13` 注释、`gen_authhash.c` 与 docs，预计算哈希随镜像发布。
- **影响**：拿到源码/镜像即可离线比对；全局静态盐让彩虹表可跨部署复用；口令截断导致长口令等价。教学演示可接受，但作为真实系统是**默认弱凭据**。
- **建议**：换 per-user 随机盐（存 shadow）、标准 KDF、去掉默认口令改为首次启动强制设置；口令截断改为显式拒绝并提示。

### M4 EL0 用户程序继承全局 root 文件权限

- **位置**：`fs.c:48` `static int fs_uid` 是**全局单一** uid，`can_mutate()` = `fs_uid==0 || in->uid==fs_uid`；`svc_dispatch` 的 `open`（`kernel.c:1652`）直接 `fs_lookup`+`fs_readfile`，未为 EL0 程序建立独立凭据。
- **影响**：shell 默认 root → 任意 `run` 加载的用户程序以 root 身份读文件，包括 `FM_PRIVATE` 的 `/etc/shadow`（哈希文件可被用户程序读出）。教学内核无进程/会话隔离，属已知简化，但应记录为权限边界缺失。
- **建议**：为 EL0 程序保存/恢复独立 uid，或在 `run` 时显式降权到调用者 uid 并禁止读取 `FM_PRIVATE`。

## 五、低危 / 信息性（L）

### L1 网络栈无认证，状态可预测
- `net.c:111-119` `arp_record` 对任何 ARP 报文无脑记录、缓存 8 条不过期 → **ARP 欺骗投毒**；DHCP 无认证 → 恶意服务器可下发假 IP/网关；`virtio_rng.c` 文件头自承"随机数靠软件 PRNG、没有真熵源" → DHCP xid / TCP ISN 可预测；`tcp.c` 单连接、仅按 `sport/dport/seq/ack` 校验 → 能回包的对端可注入数据。
- **边界校验做得好**（正面）：`on_frame len>=14`、`ip_rx tot>len/tot<ihl/ihl>=20` + 校验和、`tcp_rx` 的 `ihl/doff/slen`、`dhcp_parse len>=240` 且 `i+2+l>len` 才停、`virtio_net.c:310` `flen<=1514`，分层长度校验完整，未发现收包越界写。

### L2 `cmd_crash` 无权限门槛
- `kernel.c:3106-3112` `crash udf|brk|abort|wronly` 任何 shell 用户可主动触发未定义指令/数据中止/写只读页 → 本地 DoS。属有意的演示命令，但应至少限制为调试构建。

### L3 安装向导 / 终端命令
- `desktop.c:388-401` 安装系统有"二次确认 + 超时撤销"（正面），但确认后执行 `install yes` 会清空目标磁盘，无独立鉴权；GUI 终端 `term_key` 直接把按键喂给 `gfxterm_key`→shell，等价于在 GUI 里开了个 root shell。与 M2 是同一根因。

## 六、已确认的安全设计（正面，避免只列问题）

以下部分经核查实现正确，是这套内核做得扎实的地方：

1. **口令只存哈希、内核镜像零明文口令**：`auth_init`（`kernel.c:1939`）只把预计算哈希写进 `/etc/shadow`，登录时现场算再比对；横幅不打印口令，`test_stage5_qemu.py` 有"全程不回显/无泄漏"负断言。
2. **SHA-256 实现标准**：`crypto.c` 的尾块填充/长度场有正确的 55-rem 推导，`test_crypto.c` 覆盖性质测试。
3. **ELF 装载边界较完整**（除 H2）：入口 `USER_BASE..USER_END` 校验、段 `vaddr/memsz` 回绕检查、`filesz>memsz`、`offset/filesz` 越界、`fill_pt` 按 PXN/UXN 分离代码/数据权限（`kernel.c:1538-1561`）。
4. **SVC 用户指针校验**（除 H3）：write/read 分支都有 `p+len<p || p+len>USER_END` 与 `len>65536` 上限。
5. **文件系统路径处理**：`fs.c:292-298` `split_path` 明确"先卡长度再拷贝"（带 2026-10-28 修复注释）、`name_ok` 限制 61 字节名、`dir_add` 先校验再写、私密文件 `FM_PRIVATE` 读控制、`fs_setfile` 重写顺序保证失败可回滚。
6. **GUI 文本编辑器**：`ed_key`（`desktop.c:788/793`）插入/换行均检查 `ed_len < sizeof(ed_buf)-1`，无编辑器缓冲溢出。
7. **网络收包分层长度校验**（见 L1 正面部分）、**帧缓冲缺 GOP 时优雅降级串口 shell**、**BSS 预算守卫**防止内核镜像踩穿用户区。
