# 手机版（Android 运行 LoongOS）— 第 1 轮：启动包制作

**时间**：2026-11-07
**目标**：在安卓手机上把灵珑系统跑起来

## 结论
路线定为 **Termux + qemu-system-aarch64（TCG 软件模拟）+ `-kernel` 直载**。
理由：
- 裸机内核装不进手机（bootloader 锁 + 无手机硬件驱动）；
- QEMU virt 机器的 PL011 串口地址 0x09000000 与内核一致 → `-nographic` 下 Termux 终端即 shell；
- 内核 `handle_irq()` 已实现 UART RX 中断收字节进 ring buffer（kernel.c:853 附近），**串口输入可用**，
  不需要 usb-kbd（手机端也拿不到）。

## 证据
- `readelf -h kernel.elf` → AArch64 / EXEC / entry 0x40080000（QEMU virt RAM 起点 0x40000000，可直载）
- 内核 md5 `1f5f3b6426d45cf0ffe67a0a59e3871f`（2026-10-31 最新构建，250KB）
- `pkg` 侧：Termux 提供 `qemu-system-aarch64-headless`（外部资料核实）
- 启动脚本参数已用「假 qemu」验证：TCG 分支 → `-M virt,gic-version=2 -cpu cortex-a57`；
  KVM 分支 → `-M virt,gic-version=3,accel=kvm -cpu host`（KVM 不支持 in-kernel GICv2，必须 v3）

## 持久化
`disk.img` 128MB，手工写入 MBR（分区类型 **0x99** = LoongOS 数据分区，起始 LBA 2048，扇区数 260096）。
内核 fs 逻辑：发现 0x99 分区 → 尝试挂载 → 挂不上且分区头全零 → **自动格式化**（kernel.c:2420~2445 一段）。
故首次启动即自动建好文件系统，之后写文件重启仍在。
⚠️ 未经真机验证（NAS 铁律：不在本机起 QEMU），需用户在手机上首启观察是否打印
`[fs  ] MOUNTED-DISK lba=2048 blocks=32512 (formatted)`。
